5 صياغة المهمة كـ Seq2Seq

🔄 الفكرة الجوهرية

بدلاً من تدريب مصنّف تقليدي (Softmax)، نحوّل المهمة إلى توليد نص: النموذج يتعلم إنتاج سلسلة تحتوي على الفئة الرئيسية والفرعية معاً.

📥 المدخل (Encoder Input)

def compose_encoder_input(row):
    return (
        "المهمة: تصنيف هرمي\n\n"
        f"العنوان:\n{row['title']}\n\n"
        f"النص:\n{row['content']}"
    )

📤 المخرج (Decoder Target)

def compose_decoder_target(row):
    return (
        f"<main_class>{row['category']} "
        f"<sub_class>{row['subcategory']}"
    )
🎁
ميزة هذه الصياغة: الرموز الخاصة <main_class> و<sub_class> تعمل كـمحفّزات هيكلية تجعل النموذج يفصل بين المستويين الهرميين، ويستطيع لاحقاً استخراجهما عبر Regex.

📄 مثال حقيقي

Input :  المهمة: تصنيف هرمي
         العنوان: انطلاق المفاوضات التجارية
         النص: أعلنت وزارة التجارة اليوم...
Target: <main_class>اقتصاد <sub_class>تجارة دولية</s>

7 التوكنايز والتخزين المؤقت

🔤 دالة التوكنايز الموحّدة

def tokenize_examples(batch):
    enc = tokenizer(
        batch["input"],
        max_length=SRC_MAX_LEN,
        truncation=True
    )
    tgt = tokenizer(
        text_target=batch["target"],
        max_length=TGT_MAX_LEN,
        truncation=True
    )
    enc["labels"] = [
        t if t != tokenizer.pad_token_id else -100
        for t in tgt["input_ids"]
    ]
    return enc

💡 لماذا -100؟

🧩
في PyTorch، القيمة -100 تُخبر دالة الخسارة CrossEntropyLoss بتجاهل هذه المواقع. نضعها على رموز الحشو (padding) حتى لا يتعلم النموذج توليد <pad>.

⚡ التخزين المؤقت (Caching)

if os.path.exists(TOKEN_CACHE) and DATA_FRACTION == 1.0:

else:

8 استراتيجيات الضبط الدقيق

يدعم النظام ثلاث استراتيجيات قابلة للتبديل عبر متغير واحد FINETUNE_MODE:

🔷 LoRA

Low-Rank Adaptation
يضيف مصفوفات منخفضة الرتبة إلى طبقات الانتباه (q, v).

  • r = 16، α = 32
  • dropout = 0.05
  • ~1% معاملات قابلة للتدريب

❄️ تجميد المُشفّر

يُجمَّد الـEncoder بالكامل، ويُدرَّب الـDecoder فقط.

  • أسرع بـ2× من الكامل
  • ذاكرة أقل
  • مناسب للبيانات الصغيرة

🔥 Full Fine-tune

تدريب كل المعاملات مع Gradient Checkpointing.

  • أفضل أداء نظرياً
  • يحتاج ذاكرة عالية
  • بطيء لكن شامل

🧊 Gradient Checkpointing — نقطة حرجة

if FINETUNE_MODE == "freeze_encoder":
    for p in model.encoder.parameters():
        p.requires_grad = False
    for p in model.shared.parameters():
        p.requires_grad = True
    model.gradient_checkpointing_enable()
    model.enable_input_require_grads()  # ✅ ضروري وإلا لن يمر التدرج
else:
    model.gradient_checkpointing_enable()
    model.enable_input_require_grads()  # ✅ نفس السبب
🐛
مشكلة شائعة: عند تفعيل Gradient Checkpointing، تختفي الـgradients لأن المدخلات لا تتطلب تدرجاً. الحل: enable_input_require_grads().

9 LoRA بالتفصيل

🧮 الفكرة الرياضية

بدل تحديث المصفوفة الكاملة W (d×k)، نضيف ΔW = B·A حيث:

A ∈ ℝr×k

مصفوفة صغيرة تُهيَّأ عشوائياً بـGaussian.

B ∈ ℝd×r

مصفوفة صغيرة تُهيَّأ بأصفار مبدئياً.

r << min(d,k)

الرتبة المنخفضة تقلل عدد المعاملات بشكل هائل.

⚙️ الإعدادات المستخدمة

from peft import LoraConfig, TaskType, get_peft_model

cfg = LoraConfig(
    r=ADAPTER_RANK,             # 16
    lora_alpha=ADAPTER_SCALE,   # 32
    lora_dropout=ADAPTER_DROPOUT,# 0.05
    bias="none",
    task_type=TaskType.SEQ_2_SEQ_LM,
    target_modules=["q", "v"],  # طبقات الاستعلام والقيمة فقط
)

model = get_peft_model(model, cfg)
model.print_trainable_parameters()

لماذا q و v تحديداً؟ الأبحاث أظهرت أن تكييف مصفوفات الاستعلام والقيمة في الـAttention يكفي لتحقيق أداء ممتاز مع أقل عدد من المعاملات.

🔍 استخراج الفئات من النص المُولَّد

_MAIN_RE = re.compile(r"<main_class>\s*(.*?)\s*<sub_class>", re.DOTALL)
_SUB_RE  = re.compile(r"<sub_class>\s*(.*?)(?:</s>|$)",  re.DOTALL)

def parse_label_tokens(text):
    text = text.replace("<pad>", "").strip()
    m = _MAIN_RE.search(text)
    s = _SUB_RE.search(text)
    return (m.group(1).strip() if m else "",
            s.group(1).strip() if s else "")
🎯
استخدام Regex يجعل الاستخراج مقاوماً للأخطاء البسيطة في توليد النموذج (مسافات زائدة، ترتيب مختلف للرموز).

14 الاستنتاج (Inference)

🚀 دالتان للتنبؤ

1) مقال واحد

def predict_article(title, content, num_beams=4):
    prompt = (
        "المهمة: تصنيف هرمي\n\n"
        f"العنوان:\n{title}\n\n"
        f"النص:\n{content}"
    )
    enc = tokenizer(
        prompt,
        max_length=SRC_MAX_LEN,
        truncation=True,
        return_tensors="pt"
    ).to(model.device)

    with torch.no_grad():
        out = model.generate(
            **enc,
            max_length=TGT_MAX_LEN,
            num_beams=num_beams,
            early_stopping=True
        )

    raw = tokenizer.decode(out[0], skip_special_tokens=False)
    m, s = parse_label_tokens(raw)
    return {"main": m, "sub": s, "raw": raw}

2) دفعات

def predict_batch(items, batch_size=8):
    results = []
    for i in range(0, len(items), batch_size):
        chunk = items[i:i + batch_size]
        prompts = [
            "المهمة: تصنيف هرمي\n\n"
            f"العنوان:\n{c['title']}\n\n"
            f"النص:\n{c['content']}"
            for c in chunk
        ]
        enc = tokenizer(
            prompts,
            max_length=SRC_MAX_LEN,
            truncation=True,
            padding=True,
            return_tensors="pt"
        ).to(model.device)

        with torch.no_grad():
            out = model.generate(
                **enc,
                max_length=TGT_MAX_LEN,
                num_beams=1
            )

        for text in tokenizer.batch_decode(
            out, skip_special_tokens=False
        ):
            m, s = parse_label_tokens(text)
            results.append({"main": m, "sub": s})
    return results
⚡
Beam Search: نستخدم num_beams=4 في التنبؤ الفردي (دقة أعلى)، وnum_beams=1 في الدفعات (سرعة أعلى).
